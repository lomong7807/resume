# 2026-09-08 회사 저장소 분석 기반 프로젝트 항목 추가

## 변경 요약

로컬에 클론된 회사 저장소 세 곳(`~/lineupkorea/workspace/rainbow-monitoring`, `rainbow-collector`, `seoul-ams-engine`)을 분석해 프로젝트 섹션에 4개 항목을 추가·교체했다. 서술은 "무엇 → 문제 → 기술 선택과 이유 → 성과" 원칙을 따르고, 근거는 저장소의 설계 문서·커밋·코드·Claude 세션 기록에서 확인된 것만 썼다. 같은 날 앞서 경력 섹션을 업무 개요 중심으로 줄이고, 한양대 학과평가 시스템 항목과 학력(방송통신대 편입)을 추가했다.

## 변경 파일

- `src/data/projects.ts` — 기존 "하드웨어 모니터링 솔루션" 항목을 Rainbow Monitoring 항목으로 교체(SNMP 직접 수집·XML 파이프라인·Wireshark 서술은 저장소 근거가 없어 제거, 사용자 확인). Rainbow 수집기(C) 인수·안정화, 서울기록원 웹 취약점 조치, 서울기록원 고도화(데이터 추출 DX001 + 승인 워크플로우) 추가. 한양대 학과평가 시스템 추가
- `src/data/experience.ts` — 라인업코리아 업무 개요를 새 프로젝트에 맞춰 갱신, 수치 제거
- `src/data/skills.ts` — 도구에 Claude Code 추가
- `src/components/Projects.astro` — 기간·소속을 왼쪽 컬럼으로(경력과 통일), 같은 달 시작·종료는 한 번만 표기

## 판단/결정

- 공개 범위는 사용자 확인: 회사명·제품명 Rainbow·기관명 서울기록원 실명 사용. 내부 IP·계정·미조치 취약점·외주사명·동료 실명은 제외
- 수치 정직성: 배포 시간은 "20분~1시간 → 10분"으로 정정하고 계산이 맞지 않는 95%는 제거. DX001의 상한 20만 건은 계산 유도가 아니라 실제 요청 규모(11.5만)의 2배 마진임을 그대로 서술. 비동기 선택은 "느려서"가 아니라 경로 단일화·기존 인프라 재사용이 이유였음을 세션 기록에서 확인해 그대로 씀
- DX001은 미머지·검수 대기 상태라 종료일을 두지 않고 진행 중으로 표기
- AI 협업 방법론(훅·rules·skill 구성, 스펙 선행 → 구현 → 다각도 검증)은 사용자 요청으로 어필 소재로 드러냄
